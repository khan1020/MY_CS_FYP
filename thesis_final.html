Abstract

This thesis presents the design, development, and implementation of an intelligent AI-powered document chatbot system that leverages Retrieval-Augmented Generation (RAG) technology to enable natural language querying of uploaded documents. The system combines advanced machine learning techniques including semantic search using FAISS (Facebook AI Similarity Search), hybrid retrieval with BM25 keyword matching, and vision AI capabilities for optical character recognition (OCR) and image captioning.

The primary objective of this project is to bridge the gap between unstructured document data and user-friendly information retrieval. Unlike traditional keyword-based search systems, our chatbot understands context and provides accurate, conversational responses by integrating document embeddings with large language models (LLMs). The system supports multiple document formats including PDF, DOCX, and TXT files, while also processing images through the BLIP (Bootstrapping Language-Image Pre-training) model for visual content understanding.

Key features include secure user authentication with OTP email verification, real-time external tool integration (weather API, Wikipedia search, mathematical calculations), comprehensive chat history management, bookmark functionality for important responses, and a fully responsive web interface with dark/light mode support. The system architecture follows a modular design pattern with clear separation between authentication, document processing, query classification, hybrid retrieval, and response generation components.

Performance evaluation demonstrates that the hybrid retrieval approach (combining semantic and lexical search) achieves superior accuracy compared to single-method approaches, with average query response times under 3 seconds. The system successfully handles concurrent multi-user scenarios and maintains data persistence through a well-structured MySQL database. This research contributes to the growing field of conversational AI by providing a practical, scalable solution for intelligent document interaction suitable for educational, business, and research applications.

Keywords: Retrieval-Augmented Generation, FAISS, Natural Language Processing, Document Chatbot, Vision AI, Semantic Search, Hybrid Retrieval, Flask, Machine Learning

Chapter 1
Introduction

1.1 Background and Context

The digital age has witnessed an exponential growth in document generation across all sectors of society. Organizations, educational institutions, and individuals generate massive amounts of textual information daily in the form of reports, research papers, manuals, books, and various other document formats. While this abundance of information presents vast opportunities for knowledge creation and sharing, it simultaneously poses significant challenges in terms of information retrieval and accessibility.

Traditional document search systems rely primarily on keyword matching and lexical similarity, which often fail to capture the semantic intent behind user queries. Users must formulate precise search terms and navigate through multiple documents to find relevant information, leading to time-consuming and often frustrating experiences. The limitations of these conventional approaches become particularly evident when dealing with complex queries that require understanding context, making inferences, or synthesizing information from multiple sources.

Recent advances in artificial intelligence, particularly in natural language processing (NLP) and machine learning, have opened new possibilities for intelligent information retrieval. The emergence of large language models (LLMs) such as GPT (Generative Pre-trained Transformer), BERT (Bidirectional Encoder Representations from Transformers), and their successors has demonstrated remarkable capabilities in understanding and generating human-like text. However, these models face a critical limitation known as the "knowledge cutoff" problem—they only possess information up to their training date and cannot access or reason about new or proprietary documents.

Retrieval-Augmented Generation (RAG) has emerged as a transformative approach to overcome this limitation by combining the strengths of information retrieval systems with the natural language understanding capabilities of LLMs. RAG systems first retrieve relevant context from a knowledge base based on user queries, then use this retrieved information to generate accurate, contextually relevant responses. This paradigm shift enables AI systems to provide up-to-date, domain-specific answers while maintaining the conversational fluency of advanced language models.

The integration of vision AI capabilities further extends the horizons of document interaction systems. Many documents contain not only text but also images, diagrams, charts, and other visual elements that carry significant information. The ability to extract text from images through Optical Character Recognition (OCR) and understand visual content through image captioning models enables comprehensive document processing that captures both textual and visual information.

1.2 Problem Statement

Despite the advancements in information technology, several critical challenges persist in document interaction and information retrieval systems:

  • Limited Contextual Understanding: Traditional keyword-based search engines fail to understand the semantic meaning and context behind user queries, often returning irrelevant results or missing pertinent information.
  • Inability to Synthesize Information: Users seeking comprehensive answers often need to manually read through multiple documents and synthesize information themselves, which is time-consuming and error-prone.
  • Static Knowledge Bases: Pre-trained language models cannot access or reason about new documents without extensive and costly retraining processes.
  • Visual Information Neglect: Most document retrieval systems focus exclusively on text, ignoring valuable information contained in images, diagrams, and other visual elements.
  • Poor User Experience: Complex query interfaces and the need for precise search terms create barriers for non-technical users seeking information from document repositories.
  • Lack of Personalization: Existing systems typically do not maintain conversation history or user preferences, forcing users to repeat context in every interaction.

These challenges necessitate a more intelligent, user-friendly solution that can understand natural language queries, retrieve relevant information from document collections, process both textual and visual content, and provide accurate, conversational responses while maintaining conversation context.

Literature Review

2.1 Evolution of Chatbot Technology

The history of chatbots spans several decades, beginning with ELIZA in the 1960s, one of the first programs designed to simulate conversation. ELIZA used pattern matching and substitution methodology to simulate intelligent conversation, though it had no real understanding of language. This was followed by PARRY in 1972, which attempted to simulate a person with paranoid schizophrenia, and later by more sophisticated systems like ALICE (Artificial Linguistic Internet Computer Entity) in 1995, which won the Loebner Prize multiple times.

The evolution of chatbots can be broadly categorized into four generations:

  • Rule-Based Systems (1960s-1990s): Early chatbots relied on predefined rules and pattern matching. While limited in capability, they established the foundation for human-computer conversation.
  • Statistical Methods (1990s-2010s): Introduction of machine learning techniques enabled systems to learn from data rather than relying solely on handcrafted rules. This era saw the application of Hidden Markov Models, Support Vector Machines, and early neural networks.
  • Deep Learning Era (2010s): The advent of deep learning, particularly Recurrent Neural Networks (RNNs) and Long Short-Term Memory networks (LSTMs), revolutionized natural language understanding and generation. Sequence-to-sequence models enabled more natural conversation flow.
  • Transformer-Based Models (2017-Present): The introduction of the Transformer architecture and subsequent models like BERT, GPT, and T5 marked a paradigm shift. These models demonstrated unprecedented language understanding and generation capabilities, enabling truly conversational AI systems.

2.2 Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation represents a significant advancement in addressing the limitations of pure generative models. The concept was formally introduced by Lewis et al. (2020) in their seminal paper "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks." RAG combines the benefits of retrieval-based and generation-based approaches by first retrieving relevant documents from a knowledge base and then using this retrieved context to generate responses.

Core Principles of RAG

RAG systems operate on two fundamental components:

  1. Retriever Component: Responsible for finding relevant documents or passages from a knowledge base given a query. This can be implemented using various techniques including dense retrieval (using embeddings) or sparse retrieval (using traditional IR methods like TF-IDF or BM25).
  2. Generator Component: Takes the retrieved context along with the original query and generates a natural language response. This is typically implemented using large language models that have been trained or fine-tuned for conditional generation.

Advantages of RAG

  • Up-to-date Information: Unlike static pre-trained models, RAG systems can access and reason about current information by retrieving from updated knowledge bases.
  • Reduced Hallucination: By grounding responses in retrieved factual content, RAG systems are less likely to generate false or misleading information.
  • Transparency and Explainability: The retrieval step provides transparency by showing which sources informed the generated response.
  • Domain Adaptation: RAG systems can easily adapt to new domains by simply updating the knowledge base without retraining the underlying language model.
  • Efficiency: Compared to fine-tuning large language models, updating a retrieval index is computationally much more efficient.

2.3 Document Processing and Embeddings

Effective document processing is crucial for RAG systems. This involves several key steps:

Text Extraction

Various libraries and tools support text extraction from different document formats. PyMuPDF (fitz) excels at PDF text extraction, python-docx handles Microsoft Word documents, and standard file I/O operations process plain text files. The challenge lies in maintaining document structure, handling special characters, and preserving formatting when relevant.

Chunking Strategies

Breaking documents into semantically meaningful chunks is critical for effective retrieval. Common strategies include:

  • Fixed-size chunking: Splitting text into uniform-sized pieces (e.g., 512 tokens)
  • Sentence-based chunking: Using sentence boundaries as natural splitting points
  • Paragraph-based chunking: Maintaining paragraph integrity for better semantic coherence
  • Semantic chunking: Using models to identify topic boundaries and split accordingly
  • Overlapping chunks: Ensuring context continuity by creating overlapping segments

Text Embeddings

Text embeddings transform natural language into dense vector representations that capture semantic meaning. Popular embedding models include:

  • Sentence-BERT (SBERT): Modifications to BERT specifically designed for generating sentence embeddings efficiently. Models like 'all-MiniLM-L6-v2' provide excellent performance-to-size ratios.
  • OpenAI Embeddings: The 'text-embedding-ada-002' model offers high-quality embeddings but requires API calls.
  • Instructor Embeddings: Task-specific embeddings that can be customized with natural language instructions.
  • E5 Models: State-of-the-art open-source embedding models from Microsoft.

2.4 Vector Databases and Semantic Search

Vector databases are specialized systems designed to store and query high-dimensional vector embeddings efficiently. For semantic search applications in RAG systems, these databases are essential components.

FAISS (Facebook AI Similarity Search)

FAISS, developed by Facebook AI Research, is a library for efficient similarity search and clustering of dense vectors. It provides several key advantages:

  • Highly optimized C++ implementation with Python bindings
  • Support for both CPU and GPU acceleration
  • Multiple indexing strategies (flat, IVF, HNSW, PQ) for different speed-accuracy trade-offs
  • Ability to handle billions of vectors
  • Thread-safe operations for concurrent queries

For our RAG system, FAISS IndexFlatIP (Inner Product) provides accurate results for smaller document collections, while more advanced indices like IVF or HNSW can be employed for larger datasets requiring faster retrieval.

Alternative Vector Databases

  • Pinecone: Managed vector database with automatic scaling
  • Weaviate: Open-source vector database with GraphQL interface
  • Milvus: Open-source vector database designed for scalability
  • Qdrant: Vector database with advanced filtering capabilities
  • Chroma: AI-native embedding database focused on developer experience

2.5 Hybrid Retrieval Methods

While semantic search using dense embeddings captures contextual similarity effectively, it can sometimes miss exact keyword matches that traditional lexical search handles well. Hybrid retrieval combines the strengths of both approaches.

BM25 (Best Matching 25)

BM25 is a probabilistic ranking function used in information retrieval that considers:

  • Term frequency (TF): How often a term appears in a document
  • Inverse document frequency (IDF): How unique a term is across all documents
  • Document length normalization to prevent bias toward longer documents

BM25 excels at finding documents containing specific technical terms, acronyms, or rare keywords that semantic search might miss.

Fusion Strategies

Combining results from semantic and lexical search requires effective fusion strategies:

  • Score-based fusion: Normalizing and combining scores from both methods
  • Rank-based fusion: Using techniques like Reciprocal Rank Fusion (RRF)
  • Learned fusion: Training a model to optimally combine results
  • Re-ranking: Using a cross-encoder to re-rank candidate documents

2.6 Vision AI and Multimodal Learning

Many documents contain valuable information in visual form—images, diagrams, charts, and scanned pages. Vision AI enables systems to process and understand this visual content.

Optical Character Recognition (OCR)

OCR technology converts images of text into machine-readable text. Modern OCR systems like Tesseract, EasyOCR, and Paddle OCR use deep learning to achieve high accuracy across various fonts, languages, and image qualities. Tesseract, maintained by Google, offers:

  • Support for over 100 languages
  • Both LSTM-based and legacy recognition engines
  • Page segmentation modes for different document layouts
  • Integration with image preprocessing libraries for improved accuracy

Image Captioning

Image captioning models generate natural language descriptions of visual content. BLIP (Bootstrapping Language-Image Pre-training) represents the state-of-the-art in this domain, offering:

  • Vision encoder based on ViT (Vision Transformer)
  • Language decoder for generating captions
  • Multimodal encoder-decoder architecture
  • Pre-training on large-scale image-text pairs

Multimodal Embeddings

Models like CLIP (Contrastive Language-Image Pre-training) create unified embedding spaces for both text and images, enabling:

  • Cross-modal retrieval (text-to-image and image-to-text)
  • Zero-shot image classification
  • Visual question answering
  • Image-text similarity scoring

def hybrid_search(query, chat_id, user_id, top_k=40):
    """Perform hybrid search combining FAISS and BM25"""
    
    # Load or create indices
    faiss_index, bm25_index, paragraphs = load_indices(chat_id, user_id)
    
    if faiss_index is None:
        return []
    
    # Semantic search using FAISS
    query_embedding = embedding_model.encode([query])
    faiss_scores, faiss_indices = faiss_index.search(
        query_embedding, 
        min(top_k * 2, len(paragraphs))
    )
    
    # Lexical search using BM25
    tokenized_query = query.lower().split()
    bm25_scores = bm25_index.get_scores(tokenized_query)
    
    # Combine results with weighted scoring
    combined_scores = []
    for idx in range(len(paragraphs)):
        # Normalize scores
        faiss_score = faiss_scores[0][idx] if idx in faiss_indices[0] else 0
        bm25_score = bm25_scores[idx]
        
        # Weighted combination (70% semantic, 30% lexical)
        combined_score = 0.7 * faiss_score + 0.3 * bm25_score
        combined_scores.append((idx, combined_score, paragraphs[idx]))
    
    # Sort and return top-K
    combined_scores.sort(key=lambda x: x[1], reverse=True)
    return [para for _, _, para in combined_scores[:top_k]]

5.3.2 Text Chunking Strategy

def chunk_text(text, chunk_size=512, overlap=50):
    """
    Split text into semantically meaningful paragraphs with overlap
    
    Args:
        text: Full document text
        chunk_size: Target chunk size in words
        overlap: Number of overlapping words between chunks
    
    Returns:
        List of text chunks
    """
    # First split by double newlines (paragraphs)
    paragraphs = re.split(r'\n\s*\n', text)
    
    chunks = []
    current_chunk = []
    current_size = 0
    
    for para in paragraphs:
        para = para.strip()
        if not para:
            continue
        
        words = para.split()
        para_size = len(words)
        
        # If single paragraph exceeds chunk_size, split it
        if para_size > chunk_size:
            if current_chunk:
                chunks.append(' '.join(current_chunk))
                current_chunk = []
                current_size = 0
            
            # Split large paragraph into smaller chunks
            for i in range(0, para_size, chunk_size - overlap):
                chunk = words[i:i + chunk_size]
                chunks.append(' '.join(chunk))
        
        # If adding paragraph exceeds limit, start new chunk
        elif current_size + para_size > chunk_size:
            chunks.append(' '.join(current_chunk))
            
            # Add overlap from previous chunk
            overlap_words = current_chunk[-overlap:] if len(current_chunk) > overlap else current_chunk
            current_chunk = overlap_words + words
            current_size = len(current_chunk)
        
        else:
            current_chunk.extend(words)
            current_size += para_size
    
    # Add final chunk
    if current_chunk:
        chunks.append(' '.join(current_chunk))
    
    return chunks

from sentence_transformers import SentenceTransformer
import faiss
import numpy as np

# Load embedding model globally
embedding_model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')

def create_faiss_index(paragraphs):
    """
    Create FAISS index from text paragraphs
    
    Args:
        paragraphs: List of text chunks
    
    Returns:
        FAISS index object
    """
    # Generate embeddings for all paragraphs
    logger.info(f"Generating embeddings for {len(paragraphs)} paragraphs...")
    embeddings = embedding_model.encode(
        paragraphs,
        show_progress_bar=True,
        batch_size=32
    )
    
    # Convert to numpy array with float32 dtype (required by FAISS)
    embeddings = np.array(embeddings).astype('float32')
    
    # Create FAISS index (Inner Product for cosine similarity)
    dimension = embeddings.shape[1]  # 384 for all-MiniLM-L6-v2
    index = faiss.IndexFlatIP(dimension)
    
    # Normalize vectors for cosine similarity
    faiss.normalize_L2(embeddings)
    
    # Add vectors to index
    index.add(embeddings)
    
    logger.info(f"FAISS index created with {index.ntotal} vectors")
    
    return index

5.3.6 Hybrid Retrieval Implementation

def hybrid_retrieve(query, chat_id, user_id, top_k=40, alpha=0.7):
    """
    Perform hybrid retrieval combining FAISS (semantic) and BM25 (lexical)
    
    Args:
        query: User query string
        chat_id: Current chat session ID
        user_id: Current user ID
        top_k: Number of results to return
        alpha: Weight for semantic search (1-alpha for lexical)
    
    Returns:
        List of top-K relevant paragraphs
    """
    # Load indices
    faiss_index, bm25_index, paragraphs = load_indices(chat_id, user_id)
    
    if faiss_index is None or len(paragraphs) == 0:
        logger.warning("No documents indexed for this chat")
        return []
    
    # Semantic search with FAISS
    query_embedding = embedding_model.encode([query]).astype('float32')
    faiss.normalize_L2(query_embedding)
    
    k = min(top_k * 2, len(paragraphs))  # Retrieve more candidates
    faiss_scores, faiss_indices = faiss_index.search(query_embedding, k)
    
    # Lexical search with BM25
    tokenized_query = query.lower().split()
    bm25_scores = bm25_index.get_scores(tokenized_query)
    
    # Normalize scores to [0, 1] range
    faiss_scores_norm = faiss_scores[0] / (np.max(faiss_scores[0]) + 1e-10)
    bm25_scores_norm = bm25_scores / (np.max(bm25_scores) + 1e-10)
    
    # Combine scores
    combined_scores = {}
    for i, idx in enumerate(faiss_indices[0]):
        if idx < len(paragraphs):
            combined_scores[idx] = alpha * faiss_scores_norm[i]
    
    for idx in range(len(paragraphs)):
        if idx in combined_scores:
            combined_scores[idx] += (1 - alpha) * bm25_scores_norm[idx]
        else:
            combined_scores[idx] = (1 - alpha) * bm25_scores_norm[idx]
    
    # Sort by combined score
    sorted_indices = sorted(
        combined_scores.items(),
        key=lambda x: x[1],
        reverse=True
    )[:top_k]
    
    # Return top-K paragraphs
    results = [paragraphs[idx] for idx, score in sorted_indices]
    
    logger.info(f"Retrieved {len(results)} paragraphs for query: {query[:50]}...")
    
    return results

def preprocess_image_for_ocr(image_path):

7.3 Challenges and Solutions

7.3.1 Technical Challenges

Challenge 1: Memory Management with Large Documents

Problem: Processing very large PDFs (>100 pages) caused memory issues during embedding generation.

Solution: Implemented batch processing for embedding generation (batch_size=32) and chunk-level indexing rather than processing entire documents at once.

Challenge 2: Context Window Limitations

Problem: LLM context windows limited the amount of retrieved context that could be included in prompts.

Solution: Implemented smart context truncation, prioritizing the most relevant paragraphs and summarizing less critical context when necessary.

Challenge 3: OCR Accuracy on Poor Quality Images

Problem: OCR struggled with low-resolution or poorly lit images.

Solution: Implemented preprocessing pipeline with denoising, grayscaling, and adaptive thresholding to improve OCR input quality.

Challenge 4: Handling Ambiguous Queries

Problem: Queries like "tell me about it" without clear context were difficult to handle.

Solution: Implemented conversation history tracking and contextual prompt engineering to maintain conversation state and resolve pronouns.

7.3.2 Design Decisions and Trade-offs

Decision 1: Per-Chat vs. Global Indexing

Choice: Per-chat FAISS indices rather than global index

Rationale: Ensures queries only search within relevant document context, improves precision, simplifies index management

Trade-off: Cannot search across all user documents simultaneously; requires more storage

Decision 2: Streaming vs. Batch Responses

Choice: Streaming response generation

Rationale: Improves perceived performance, allows users to start reading while response generates

Trade-off: More complex frontend implementation; cannot edit/retry responses easily

Decision 3: Self-Hosted vs. Managed Vector Database

Choice: Local FAISS with file persistence

Rationale: Full control, no API costs, works offline, simple deployment

Trade-off: Limited scalability compared to managed solutions like Pinecone

Appendix F: User Manual

F.1 Getting Started

  1. Navigate to the application URL in your web browser
  2. Click "Register" and fill in your details
  3. Check your email for the 6-digit OTP
  4. Enter the OTP to complete registration
  5. You'll be automatically logged in and redirected to the chat interface

F.2 Uploading Documents

  1. Click the paperclip icon in the input area
  2. Select a PDF, DOCX, or TXT file from your computer
  3. Wait for the file to upload and index (progress shown)
  4. File will appear as a chip above the input area
  5. You can now ask questions about the document

F.3 Asking Questions

  • Document Questions: "Summarize chapter 3", "What does the document say about X?"
  • Weather Queries: "What's the weather in Hyderabad?"
  • Wikipedia Queries: "Who is Albert Einstein?"
  • Calculations: "Calculate 15 * 23 + 47"

F.4 Managing Chats

  • Create new chat: Click "+ New Chat" button
  • Switch chats: Click on a chat in the sidebar
  • Rename chat: Click the pencil icon next to chat title
  • Delete chat: Click the trash icon (requires confirmation)

F.5 Using Bookmarks

  1. Hover over an AI response you want to save
  2. Click the bookmark icon
  3. Add a title, tags, and notes (optional)
  4. Access bookmarks from the main menu
  5. Export bookmarks to PDF from the bookmarks page

F.6 Customization

  • Theme: Click the sun/moon icon to toggle dark/light mode

  • Sidebar Width: Drag the sidebar edge to resize
